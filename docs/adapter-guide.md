# 适配器指南 · 让一个漫画网站被支持

> 目标：**照着做 10 分钟加一个网站**。全程只需改文件末尾的 `ADAPTERS` 数组。

---

## 一、先理解两个概念

脚本只认识两样东西：

| 概念 | 意思 | 例子 |
|---|---|---|
| **条目 (item)** | 页面上「一部漫画」所占的那块区域 | 一张封面卡、列表里的一行 |
| **标签 (tag)** | 条目上可点击的分类词 | 「恋爱」「完结」「作者：某某」 |

适配器的工作就是告诉脚本：**条目在哪儿**、**每个条目的标签藏在哪儿**。

---

## 二、动手前：用 F12 找出 3 个选择器

打开目标漫画站的列表页，按 `F12` 打开开发者工具。

### 第 1 步 · 找条目选择器

1. 点开发者工具左上角的**小箭头**（元素选取器）。
2. 在页面上**点一部漫画的封面**。
3. 看右侧高亮的 HTML，往上找**包裹整部漫画的最外层标签**。
4. 记下它的 `class` 或 `id`。

> 例如高亮部分最外层是 `<div class="manga-card">` → 选择器写成 `.manga-card`。

**判断标准**：这个选择器在页面上选出来的元素数量，应该**正好等于漫画数量**。
在开发者工具的 Console 里粘这行验证（把选择器换成你的）：

```js
document.querySelectorAll('.manga-card').length
```

返回的数字和页面上的漫画数量一致 → 正确。

### 第 2 步 · 找标签选择器

1. 还是用小箭头，这次**点漫画卡片上的一个标签**（比如「恋爱」）。
2. 看它的 `<a>` 标签，重点看 `href` 属性。

典型情况有三种，对号入座：

| 情况 | HTML 长什么样 | 用什么选择器 |
|---|---|---|
| A. 标签链接里带 `tag` | `<a href="/tag/romance">恋爱</a>` | `a[href*="tag"]` |
| B. 标签有专属 class | `<span class="tag-item">恋爱</span>` | `.tag-item` |
| C. 标签存在 data 属性里 | `<div data-tags="恋爱,校园">` | 读属性，不是选择器 |

**多数站点属于 A 或 B**。把两种情况都写进去更保险。

### 第 3 步 · 记下站点域名

看地址栏，把域名记下来，例如 `www.example-manga.com`。

---

## 三、写适配器：直接复制这个模板

打开 `src/manga-tag-lens.user.js`，找到 `ADAPTERS` 数组，把这个对象加到**最后一项 `generic` 的前面**。

```js
ADAPTERS.push({
  id: 'example-manga',                       // 唯一标识，随便起但别重复
  name: 'Example 漫画站',                     // 面板日志里显示的名字
  test: () => /(^|\.)example-manga\.com$/.test(location.hostname),  // 域名匹配

  itemSelector: '.manga-card',               // ← 第 1 步的结果

  getItemTags(el) {
    const out = [];
    // ← 第 2 步的结果，按需保留下面任意一行或全部
    qsa(el, 'a[href*="tag"]').forEach((a) => out.push(txt(a)));
    // qsa(el, '.tag-item').forEach((n) => out.push(txt(n)));
    // (el.getAttribute('data-tags') || '').split(',').forEach((s) => out.push(s));

    return uniq(out.map(cleanLabel).filter(Boolean));   // 返回页面上的原文，引擎负责简繁和大小写
  },

  getItemTitle: (el) => txt(el.querySelector('.title')),  // 可选，取标题
});
```

### 字段速查

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | 唯一字符串 |
| `name` | ✅ | 给人看的名字 |
| `test()` | ✅ | 返回 `true` 表示「当前就在这个站点」。用 `location.hostname` 判断 |
| `itemSelector` | ✅ | 条目选择器，多个用逗号分隔（CSS 语法） |
| `getItemTags(el)` | ✅ | 传入条目元素，返回标签字符串数组 |
| `getItemTitle(el)` | ❌ | 取漫画标题，用于调试 |
| `tagSelector` | ❌ | 页面上「全部标签」区域。暂未使用，可省略 |

### 关于那几个工具函数（必须保留）

| 函数 | 作用 | 能不能省 |
|---|---|---|
| `qsa(root, sel)` | 安全查询，选择器写错不会让整页崩 | 建议保留 |
| `txt(el)` | 取纯文本并去掉首尾空格 | 建议保留 |
| `cleanLabel(s)` | 去掉首尾空白。适配器返回原文，好让面板显示网站自己的写法 | 建议用它收尾 |
| `norm(s)` | 引擎用来折叠大小写、空白、简体繁体。适配器不用自己调用 | 引擎里，别改 |
| `uniq(arr)` | 数组去重 | **必须保留** |

最后一行固定这么写，不要改：

```js
return uniq(out.map(cleanLabel).filter(Boolean));
```

不要在适配器里 `toLowerCase`。`无修正` 和 `無修正` 会在引擎里算成同一个。

## 四、验证

1. 在 Tampermonkey 里保存脚本。
2. 刷新漫画站列表页。
3. 按 `F12` 看 Console，应该出现：

```
[MTL] 已启动，适配器：Example 漫画站，条目 48 个，标签 216 种
```

4. 右上角面板出现标签列表 → **成功**。

### 排查表

| Console 里看到什么 | 原因 | 怎么修 |
|---|---|---|
| 什么都没有 | 域名没匹配上 | 检查 `test()` 里的正则，注意 `.` 要写成 `\.` |
| `当前页面未识别到带标签的漫画条目` | 条目没选出来，或条目里没取到标签 | 回到第二步，用 `document.querySelectorAll()` 重新验证 |
| 标签列表里出现一串**没见过的怪词** | 选择器太宽，抓到了别的东西 | 把 `a[href*="tag"]` 收窄，例如改成 `a[href*="/tag/"]` |
| 条目数明显偏少 | 选择器太窄，或元素被判定为不可见 | 放宽选择器；脚本会用宽高过滤掉隐藏节点，这是正常的 |
| 标签名带多余文字 | 链接内混了图标或计数 | 改用更精确的子元素，如 `txt(a.querySelector('span'))` |

## 六、设计原则（如果想改引擎，先读这里）

1. **适配器只描述结构，不做判断。** 筛选逻辑永远在 `matches()` 里，不要往适配器里塞业务逻辑。
2. **不改卡片内部结构。** 高亮只加 `data-mtl` 属性。对上的漫画会把外面那一格挪到同一排的最前面，清空时按原顺序放回去。刷新页面也会回到原样。
3. **打开页面时绝不发网络请求。** 标签从当前页 DOM 提取。简繁库用文件头的 `@require`，只在安装脚本时下载一次。
4. **UI 必须放 Shadow DOM 里。** 否则漫画站的全局 CSS 会把面板搞变形。
5. **新功能优先做成通用能力**（如标签归并、方案保存），而不是给某个站点开小灶。
